pubDate: 2026-07-27

自分の個人プロジェクト5つで、AI コーディングエージェント向けの設定（`CLAUDE.md` とサブエージェント定義）を一斉に見直した。目的は「ベストプラクティスに寄せる」くらいの軽い気持ちだったのだが、開けてみたら**規約の側が壊れていた**。

しかも壊れ方が厄介で、どれもエラーにならない。人間なら「あれ？」と引っかかる記述に、AI は疑わずに従ってしまう。

## 症状1: 規約が実装と食い違っている

Next.js のサイト（静的エクスポート）で、規約ドキュメントを現行コードから書き直したところ、既存の規約に誤りが3件見つかった。

| 規約に書いてあったこと | 実態 |
| --- | --- |
| 全 page に `export const dynamic = "force-static"` を付ける／指定漏れを検出して修正する | `src/app/**/page.tsx` 46 ファイルに**1件も無い**。`output: "export"` では全ルートが静的化されるので page 側の指定は不要 |
| `page.tsx` に `metadata` を書く | page はほぼ `"use client"` なので `metadata` を export できない。実際は**同階層の `layout.tsx`** が持っている（40ファイル） |
| `pnpm test` で全テストが走る | vitest の `projects` は `storybook` / `unit` / `worker` の3つ。`storybook` は Playwright + Chromium を起動する |

1つ目が一番危なかった。この規約に従って SEO 担当のサブエージェントに「指定漏れの監査」をさせていたら、**46ページ全部に無意味な行を足していた**。テストは通る。ビルドも通る。レビューでは「規約どおりですね」で終わる。

人間が規約を読むときは、書いてあることと目の前のコードが食い違っていたら手が止まる。AI は止まらない。**規約ドキュメントは、AI に渡した瞬間から「読み物」ではなく「実行される仕様」になる。**でも実装と同期する仕組みは誰も付けていない。

3つ目にも副作用があった。以前「storybook プロジェクトは環境依存で落ちるから除外」という回避策をメモしていたのだが、その回避策が `worker` プロジェクトまで巻き込んで落としていた。**回避策そのものが腐っていた**わけで、これも誰も気づかない類の壊れ方だった。

## 症状2: `CLAUDE.md` が6日で倍近くに膨らんでいた

別のプロジェクト（Python のデスクトップアプリ）では、規約の中身ではなく**量**が問題になっていた。

```
2026-07-21   29KB
2026-07-27   55KB   (+90%)
```

6日で倍近い。しかも増分の 68% が「設計上の判断」という1つの節だった。実測値や失敗の記録を、その都度 `CLAUDE.md` に追記していた結果だ。

`CLAUDE.md` は全セッションの先頭に丸ごと載る。つまり**毎回のコンテキストを固定で食う**。にもかかわらず、これが膨らんでいることに誰も気づけない構造になっている。

> 差分レビューでは増分しか見えない。総量には誰も気づかない。

+2KB のコミットは毎回まっとうに見える。実際、1つ1つの追記は正しかった。正しい追記が積み上がって全体が壊れる、というのは差分レビューが構造的に苦手なやつだ。

## 対処1: 「予算」をテストで縛る

分割して 26KB まで落としたあと、**同じことがまた起きたら気づけるように、サイズの上限をテストにした**。

```python
# 分割直後 26.2KB に対する上限。伸びしろは残すが、倍になる前に止まる。
CLAUDE_MD_BUDGET = 34_000


def test_claude_md_stays_within_budget():
    size = len(CLAUDE_MD.read_bytes())
    assert size <= CLAUDE_MD_BUDGET, (
        f"CLAUDE.md が {size} バイトで予算 {CLAUDE_MD_BUDGET} を超えた。"
        "行を削るのではなく、実測値や失敗の記録を docs/design-rationale.md へ移すこと。"
    )
```

ポイントは assert メッセージに**「どう直すか」を書いた**こと。ただ「超えた」とだけ言われると人は行を削る。削られて困るのは、たいてい一番大事な「なぜそうしたか」の部分だ。だから逃がし先を明示しておく。

分割そのものにも一手間かけた。`CLAUDE.md` の太字は「ここは地雷」という標識として使っていたので、**太字179件を分割前後で機械的に照合**して、1件も落ちていないことを確認した（実際1件だけ言い換えで消えていたので戻した）。目視だと絶対に見落とす。

## 対処2: 参照切れもテストで縛る

同じテストファイルに、こういうものも足した。

- `CLAUDE.md` が案内しているスラッシュコマンドが、実際に `.claude/commands/` に存在するか
- `settings.json` が参照しているフックのスクリプトが、実際に存在するか
- 根拠ドキュメント側に増えた節が、`CLAUDE.md` からリンクされているか

どれも「切れても何も起きない」参照だ。存在しないコマンドを案内されたエージェントは、黙って手作業に戻る。リンクの無い節は誰にも読まれず、規則だけが独り歩きする。フックのパスが切れれば、規則が黙って効かない状態に戻る。

**AI 向けの設定は、壊れても例外が飛ばない。**だから壊れたことを検出する仕掛けを自分で足すしかない。

## 症状3: フックが「成立してから一度も動いていなかった」

その「黙って効かない」を地で行っていたのがこれ。保存時に prettier をかける PostToolUse フックが、

```
jq でstdinのJSONを読む → pnpm dlx prettier で整形 → || true
```

という作りになっていた。ところがこのマシンには `jq` が入っておらず、pnpm ランチャも壊れていた。つまり**このフックは設定された時から一度も整形していなかった可能性が高い**。末尾の `|| true` が失敗を握りつぶし、実行時のステータス表示だけは毎回出るので、動いているように見えていた。

さらに悪いことに、`/check`（完了前チェック）の側には「フックが常に整形するので format はスコープ外」と書いてあった。**整形を担保する主体が、誰もいない状態**になっていた。

直したのは3点。

- フックは**リポジトリの依存 + Node だけ**で完結させる。stdin の JSON は `jq` ではなく Node で読む
- **`|| true` を外す。** PostToolUse の exit 1 は非ブロッキング（ツール呼び出しは成功のまま）で stderr がユーザーに見えるので、黙って無効化されるより exit 1 のほうがいい
- 「別の仕組みが担保している」と書くときは、**その仕組みが実際に動くことを確認してから書く**

ちなみに直した直後、既存の `CLAUDE.md` のテーブルまで再整形された。それだけ長いあいだ整形が効いていなかったという証拠でもある。

## 置き場所を決めると、腐りにくくなる

もう1つ効いたのが、**書く場所を役割で分けた**こと。1ファイルに全部書くと、更新すべき箇所が分からなくなって放置される。

| 置き場所 | 何を書くか |
| --- | --- |
| `docs/rules/` | コードから読み取れない**意図**、外すと壊れる**制約**、過去に間違えた**判断** |
| `docs/knowledge/` | 再現性のある**落とし穴**（外部サイトが403になる、この方法は空振りする等） |
| エージェントのメモリ | **マシン固有**のこと（pnpm が壊れている等。リポジトリには書かない） |

そして規約側の第一原則を「**このリポジトリを読めば分かることは書かない**」にした。一般的な TypeScript / React の作法も書かない。これを守るだけで量は勝手に減る。

ここで1つ実感があって、**新しいファイルを作るのは最後の手段にしたほうがいい**。知見が出るたびにファイルを増やすと、どれも読まれなくなる。既に機能している置き場所（実際に参照されているテーブルなど）に追記するほうが、はるかに生き残る。

余談だが、規約を `.agent/` という git submodule に置いていた時期があり、参照先リモートが消えて submodule ごと除去された結果、**中身が丸ごと失われた**（バックアップ無し）。しかも `.gitignore` には `.agent/` が残っていたので、同じ場所に書き直すとまた消える。規約を gitignore されたディレクトリに置かない、というのは笑い話に見えて実際に踏む。

## まとめ

- AI に渡した規約は「読み物」ではなく**実行される仕様**になる。実装との食い違いは、静かに無意味な変更として現れる
- `CLAUDE.md` は毎回のコンテキストを固定で食うのに、**差分レビューでは総量が見えない**。サイズを予算としてテストで縛る
- 参照切れ・フックの死は例外を出さない。**存在確認をテストにする**
- `|| true` で失敗を隠さない。黙って無効化されるより、うるさく失敗するほうがいい
- 書く場所を「意図 / 落とし穴 / マシン固有」で分ける。**リポジトリを読めば分かることは書かない**

規約を書くところまでは皆やる。でも規約が実装から剥がれていくのを検出する仕組みは、テストと違って誰も用意していない。AI に読ませるなら、そこまでがセットになる。
