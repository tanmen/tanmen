作っていたデスクトップツールの一部機能を有料化して、決済から利用開始までを通した。構成はこう。

- **アプリ**: Python + PySide6、PyInstaller で exe 配布
- **決済**: Stripe Payment Link（月額 ¥100 / 年額 ¥1,000）
- **ライセンス**: Cloudflare Workers + D1。Stripe の webhook を受けてキーを発行
- **LP と配布**: Cloudflare Pages と R2

技術的には難しいことはしていない。にもかかわらず何度も止まった。そして止まった原因が、**4つとも「エラーが出ない」種類だった**。ビルドは緑、webhook は 200、テストも通る。それなのに製品として壊れている。

同じ形の罠なので、症状 → 原因 → 検死方法の順で並べておく。

## 罠1: urllib の既定 User-Agent が Cloudflare に弾かれる

**症状**: アプリからライセンス登録が一切通らない。画面には「ライセンスサーバがエラーを返しました (403)」としか出ない。

**原因**: Python の `urllib` は既定で `Python-urllib/3.x` と名乗る。これを Cloudflare が **403（error code 1010）** で弾いていた。しかも返ってくるのは JSON ではなく HTML のエラーページなので、アプリ側からは何も読み取れない。

タチが悪いのは、**サーバ側は何も悪くない**ことだ。Worker のログを見ても、そもそもリクエストが到達していない。D1 も正常。ローカルの `curl` では通る。「動くはずなのに動かない」状態で、原因が自分のコードの外側にある。

**検死**: UA を変えて叩き比べれば一目でつく。

```bash
curl -s -o /dev/null -w "%{http_code}\n" -A "Python-urllib/3.10" -X POST \
  https://<worker>/verify -H 'Content-Type: application/json' -d '{"key":"...","device":"x"}'
# 403 なら UA が原因
```

**対処**: 明示的に名乗る。そしてこれは「消すと全ユーザーの登録が通らなくなる」種類の1行なので、消さないことをドキュメントに書いた。

## 罠2: PyInstaller の `--collect-submodules` が、警告も出さずに0件を返す

**症状**: ビルドは成功する。出来上がった exe を起動すると、その瞬間に落ちる。

```
ModuleNotFoundError: No module named 'kawarin.gui'
  File "kawarin\hotreload.py", line 96, in _make_window
```

**原因**: GUI を `importlib.import_module()` で動的に読んでいるので、PyInstaller の静的解析では追えない。それは分かっていたので `--collect-submodules kawarin` を指定していた。

ところが**この収集は隔離された子プロセスで走り、その `sys.path` にリポジトリ直下が入らない**。パッケージをインストールせずソースを置いているだけの構成だと、子プロセスからは見えない。そして見つからなかったとき、`collect_submodules()` は**警告も出さずに空リストを返す**。

結果、exe に入ったモジュールが2つだけになった。ビルドログには何も出ない。CI は緑。

**対処**: `PYTHONPATH=.` を渡すと 2 → 32 モジュールになった。ただしこれは「次に誰かが消したらまた壊れる」ので、**ビルド後に成果物の TOC を検査して主要モジュールが入っているかを数える**ステップを CI に足した。人の目では防げない種類の壊れ方なので、機械に数えさせるしかない。

## 罠3: Stripe の secret 取り違えは、「キーは発行されるのに解約が効かない」形で出る

これが一番きれいに騙された。

**症状**: 購入 → webhook → ライセンスキー発行、まで通る。ユーザーには正しくキーが表示される。何も問題がないように見える。

**原因**: `STRIPE_SECRET_KEY` に `whsec_...`（Webhook の署名シークレット）を入れていた。すると、

1. 署名検証は別の環境変数（`STRIPE_WEBHOOK_SECRET`）を使うので**通る**
2. webhook は 200 を返し、ライセンスキーも**発行される**
3. しかし Stripe API 呼び出しが 401 になり、サブスクリプション情報が取れない
4. 結果、`expires` が**空**のライセンスができる
5. 空の期限は「期限なし」と解釈されるので、**解約しても止まらない**

つまり「無料で永久ライセンスを配る」という、収益化としては最悪の壊れ方をする。しかも**購入者からは正常に見える**ので、誰も報告してくれない。

**検死**: 決め手は D1 の `expires` だけを見ること。

```powershell
npx wrangler d1 execute kawarin-licenses --remote --command "SELECT key,status,expires FROM licenses"
```

`expires` が入っていれば `sk_live_` が正しい（Stripe API を叩けている）。空なら 401 で弾かれている＝取り違え。**キーが出たことだけで安心しない。**

本番化のときは実際に自分で1件買って、この `expires` が入っているかを確認した。前回テストモードで同じ形の失敗を踏んでいたので、「どこを見れば分かるか」を事前に1つに絞れたのが効いた。

## 罠4: 非公開リポジトリの Releases は、匿名だと 404

**症状**: タグを push → ビルド成功 → Release 作成成功。LP のダウンロードボタンを（ログアウト状態で）押すと 404。

**原因**: リポジトリが非公開なので、Releases の資産は匿名では取得できない。開発者はログイン済みなので、自分でテストすると普通にダウンロードできてしまう。

**対処**: 配布の本体を R2 に移し、LP からは `dl.<domain>/...` を指す。そのうえで、**アップロード直後に匿名で HEAD を投げて 200 とサイズを確かめる**ステップをワークフローに入れた。

ここを自動で見ないと「ビルドは緑なのに LP のダウンロードが 404」に気付けない。実際にその状態を一度作った。

## 4つに共通していたこと

並べてみると全部同じ形をしている。**失敗が成功の顔をしている。**

| 罠 | 表向き | 実態 |
| --- | --- | --- |
| urllib の UA | サーバがエラーを返した | リクエストが到達していない |
| `--collect-submodules` | ビルド成功 | 中身が空の exe |
| secret 取り違え | キー発行成功 | 解約が効かないライセンス |
| Releases の 404 | リリース成功 | 誰もダウンロードできない |

普通のバグは、テストを書けば落ちる。この4つはどれも、**自分の環境・自分のアカウントで試すと通ってしまう**。開発者だけが踏まない。

なので対処の型も同じになった。

1. **通しで1件、本物を買う。** テストモードでは3番目の罠は絶対に見つからない（本番の secret でしか起きない）
2. **決め手になる1つの値を先に決めておく。** 「キーが出た」ではなく「`expires` が入っている」。曖昧な成功判定は、曖昧なまま通過する
3. **匿名・外部から確認するステップを自動化する。** ログイン済みの自分は、購入者と違うものを見ている

## おまけ: テストで作ったライセンスは本番の台帳に残る

D1 はテストモードと本番モードで共有される。テストモードの購入で発行したライセンスは、**一円も払われていないのに本番の台帳に `active` で残る**。

本番化のときに落とした。ただし削除ではなく失効にした。

```sql
UPDATE licenses SET status='canceled' WHERE key='<テストで出たキー>';
```

取引記録として後から追えるほうがいいので。あと、うっかり自分の PC のアプリがテストキーで動いていて、失効させたら無料版に戻る、というオチも付いた（本番キーで登録し直して解決）。

## まだ確かめていないこと

正直に残しておく。仕組み上、時間が経たないと確かめようがないものだ。

- **更新（2か月目の課金）** — `customer.subscription.updated` で `expires` が伸びる想定だが、1か月経つまで試せない
- **年額の途中解約** — Stripe は `cancel_at_period_end` を立てるだけで、`deleted` は1年後に飛ぶ
- **消費税** — 外税で売る形にしてあるが、Stripe Tax は未設定

「確かめていない」と書いておくと、次に触るときの自分が疑ってくれる。緑のログを信用しすぎて4回止まった身としては、これも立派な対策のつもりでいる。
